# git-hook-pure v4.0.0

Version 4 replaces the brittle injected dispatcher with a fail-closed,
transactional installer while keeping the repository-owned `.githooks`
interface.

Highlights:

- Preserves every Git argument for every global and hook-specific handler,
  including paths and handler names containing spaces.
- Replays exact stdin to every managed handler and existing hook for
  stream-driven hooks, so one reader cannot bypass a later policy.
- Supports normal repositories, nested monorepo directories, linked
  worktrees, and submodules using Git-owned path resolution.
- Refuses setup when any visible `core.hooksPath` is configured, before
  changing project or Git state.
- Makes local npm installation attempt hook setup automatically while keeping
  failures non-fatal and actionable; explicit setup, removal, and skip controls
  remain available when npm policy or the repository environment requires them.
- Adds `npx git-hook-pure@4.0.0 install-standalone [path]` as the recommended one-time
  bootstrap for vendoring the package's exact executable into a project.
- Ships one deterministic standalone executable with a SHA-256 manifest.
- Adds reviewed Draft Release creation and verified release-asset publishing.
- Gives hook install and uninstall one preflighted transaction owner, including
  rollback for HUP, INT, QUIT, PIPE, and TERM; incomplete rollback retains its
  recovery backups.
- Runs standalone hook setup from the verified staged executable, then
  publishes that executable last. A boundary interruption converges on rerun
  instead of pretending two processes share one rollback transaction.
- Uses exact v4 ownership metadata in a fixed wrapper envelope (with exact
  historical v3 default migration) so unknown marker content and original hook
  bytes are never guessed away.

This release requires Git 2.31 or newer. Bare repositories are intentionally
unsupported because they have no project worktree in which to own `.githooks`.
Unmapped repositories using `git init --separate-git-dir` are also rejected
because a receive hook cannot recover the detached worktree from that Git
directory. An explicit valid local `core.worktree` mapping is supported.

Version 4 was developed with substantial AI assistance under maintainer-owned
requirements, review, and testing. The human-written v3.3.0 release remains available
for provenance policies that require it, but it does not include v4's fixes and
verification guarantees.
