# git-hook-pure v4.0.0

2026-08-28

## Highlights

Version 4 replaces the brittle injected dispatcher with a fail-closed, transactional installer while keeping the repository-owned `.githooks` interface, and ships one deterministic standalone executable with a checksum manifest. It requires Git 2.31 or newer; bare repositories and unmapped `git init --separate-git-dir` layouts are intentionally rejected because a receive hook cannot recover a project worktree from them, while an explicit valid local `core.worktree` mapping is supported. Version 4 was developed with substantial AI assistance under maintainer-owned requirements, review, and testing; the human-written v3.3.0 release remains available for provenance policies that require it, but it lacks v4's fixes and verification guarantees.

## Changes

- **Breaking changes** — Git 2.31 or newer is required, bare repositories are rejected, and managed handlers now run before compatible pre-existing hook content. [`b24bd3b`](https://github.com/bolasblack/git-hook-pure/commit/b24bd3b53c5e8c011c851d9aafcdcef985b83536)
- **Argument and stdin fidelity** — every Git argument reaches every global and hook-specific handler, including paths and handler names containing spaces, and the four stream-driven hook types replay exact stdin independently to each handler and existing hook so one reader cannot bypass a later policy. [`b24bd3b`](https://github.com/bolasblack/git-hook-pure/commit/b24bd3b53c5e8c011c851d9aafcdcef985b83536)
- **Real Git layouts** — normal repositories, nested monorepo directories, linked worktrees, submodules, and non-bare receive hooks resolve through Git-owned path resolution, and any visible `core.hooksPath` is refused before project or Git state changes. [`b24bd3b`](https://github.com/bolasblack/git-hook-pure/commit/b24bd3b53c5e8c011c851d9aafcdcef985b83536)
- **Transactional install and uninstall** — both commands are preflighted, idempotent, and fail-closed, roll back on ordinary failures and HUP, INT, QUIT, PIPE, and TERM, and retain recovery backups if a rollback cannot finish; exact v4 ownership metadata lives in a fixed wrapper envelope, only complete historical v3 default blocks are migrated, and existing hook bytes and modes are restored exactly. [`b24bd3b`](https://github.com/bolasblack/git-hook-pure/commit/b24bd3b53c5e8c011c851d9aafcdcef985b83536)
- **Standalone executable and bootstrap** — one deterministic single-file executable ships with a `SHA256SUMS` manifest, `npx git-hook-pure@4.0.0 install-standalone [path]` vendors that exact executable into a project, and the checksum-verifying downloader runs hook setup from the staged file and publishes it only after setup succeeds. [`b24bd3b`](https://github.com/bolasblack/git-hook-pure/commit/b24bd3b53c5e8c011c851d9aafcdcef985b83536)
- **npm lifecycle** — local npm installation attempts hook setup automatically, keeps failures non-fatal and actionable, and offers explicit setup, removal, and skip controls for restrictive npm policies. [`b24bd3b`](https://github.com/bolasblack/git-hook-pure/commit/b24bd3b53c5e8c011c851d9aafcdcef985b83536)
- **Windows Git Bash** — the npm command adapter resolves Windows drive paths, the standalone installer accepts CRLF and `*`-prefixed `SHA256SUMS` entries, and the test suite now runs on Ubuntu, macOS, and Windows. [`71ccf17`](https://github.com/bolasblack/git-hook-pure/commit/71ccf170c68bd119c2d72899850a557125a99d65)
- **Reviewed releases** — a single SHA-pinned `draft-release` workflow verifies the tag, reruns the tests, rebuilds the executable, and attaches exactly `git-hook-pure` and `SHA256SUMS` to an unpublished draft that a maintainer reviews and publishes. [`b24bd3b`](https://github.com/bolasblack/git-hook-pure/commit/b24bd3b53c5e8c011c851d9aafcdcef985b83536) [`517e5bd`](https://github.com/bolasblack/git-hook-pure/commit/517e5bdf7eed98eaca7ae0c0a95c66112f2ae277)
